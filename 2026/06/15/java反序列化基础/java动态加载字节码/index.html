1.字节码

字节码就是可以在java虚拟机上执行的指令，存储在.class文件下，可以由JVM运行

类加载过程

双亲委派机制

指的是在类加载是先让父类加载器去优先加载，如果没有加载到类再使用本ClassLoader加载

2.URLClassLoader

ClassLoader是所有加载器的父类。那URLClassLoader可以来加载远程的.class，来获得Class，再通过反射调用。

三种路径情况

  • URL未以斜杠 / 结尾，则认为是一个JAR文件，使用 JarLoader 来寻找类，即为在Jar包中寻找.class文件
  • URL以斜杠 / 结尾，且协议名是 file ，则使用 FileLoader 来寻找类，即为在本地文件系统中寻找.class文件
  • URL以斜杠 / 结尾，且协议名不是 file ，则使用最基础的 Loader 来寻找类

3.ClassLoader

上面说到这个类，就详细了解一下

加载器在加载字节码获得类时，都会调用ClassLoader三个方法

  • loadClass：作用是从已加载的类缓存、父加载器等位置寻找类（这里实际上是双亲委派机制），在前面没有找到的情况下，执行findclass
  • findClass 的作用是根据基础URL指定的方式来加载类的字节码，然后交给defineClass
  • defineClass 的作用是处理前面传入的字节码，将其处理成真正的Java类

一般loadClass和defineClass都是不用重写的，而defineClass也不能重写。在URLClassLoader中就重写了findClass

5.BCEL ClassLoader

全名：com.sun.org.apache.bcel.internal.util.ClassLoader

它本来是给 Apache BCEL 库用的，BCEL 能把 Java 类用一套自定义的文本格式描述出来。这个 ClassLoader 的 loadClass 方法，会在找不到类时把这个字符串解析成字节码，然后 defineClass。

BCEL提供的两个类 Repository 和 Utility，Repository 用于将一个Java Class

先转换成原生字节码，当然这里也可以直接使用javac命令来编译java文件生成字节码； Utility 用于将原生的字节码转换成BCEL格式的字节码

这里还有一些坑就BECL编码的类不能太复杂，import越少越好，代码块也是越简单越好，反正我是报错一大堆
