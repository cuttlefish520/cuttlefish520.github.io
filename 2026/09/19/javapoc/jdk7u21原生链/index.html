原生链不依赖其他包，分析jdk源码就行

利用链分析

7u21原生链的关键点是sun.reflect.annotation.AnnotationInvocationHandler，之前cc1链的时候，有一个链是利用动态代理来作为链的触发点，用到的关键类也是AnnotationInvocationHandler。

动态代理实现是java.lang.reflect.Proxy,会创建一个代理对象，执行接口方法会自动调用InvocationHandler接口的invoke方法，从而实现原接口没有的方法。

AnnotationInvocationHandler实现了 InvocationHandler、Serializable，是 Java 注解运行时的动态代理处理器。注解本质是接口（@interface 编译后是继承 Annotation 的接口），接口不能直接实例化；当你调用 getAnnotation() 获取注解对象时，JDK 用 Proxy 在内存生成代理类 $ProxyN，这个代理对象的调用处理器就是 AnnotationInvocationHandler。

下面看equalsImpl()

AnnotationInvocationHandler::equalsImpl()

这个方法是Proxy.equals转发后的具体实现，功能：判断两个注解实例是否相等。注解相等规则：注解类型相同，并且所有注解成员（属性）的值全部相等。这里for会遍历拿到this.type注解对象@..Class的方法，但我们可以通过反射修改type的属性为TemplatesImpl.class，非注解就会走到var8 = var5.invoke(var1);，这里就会拿到TemplatesImpl#getOutputProperties()，触发

看一眼getMemberMethods

往上找equalsImpl()的实现

AnnotationInvocationHandler::invoke()

这里会判断调用方法是equals时，比较方法是获得方法名转成String再比较字符串。后面还有toString hashCode的注解代理转接的方法

那现在去看，怎么触发Proxy.equals(TemplatesImpl)

有一个比较常见调用equals的地方就是集合set，在集合中不允许存在重复的对象，所以一定会存在比较的方法

看一下HashSet::readObject()

HashSet::readObject()

HashSet 是Java 的集合类，底层包装 HashMap，HashSet 的元素全部作为 HashMap 的 key value 统一放一个静态常量 PRESENT

for部分循环读取HashSet的元素，把key和PRESENT填入map。跟进看put

HashMap.put

int hash = hash(key);int i = indexFor(hash, table.length);这里计算hsah值，再通过hash值计算在Entry数组里的下标。HashMap 底层是Entry 数组（table，哈希桶数组）。 hash(key) 算出哈希值，再用 indexFor(hash, table.length) 算出数组下标 i； table[i] 就是哈希桶，同一个下标，多个 Entry 用单向链表串在一起。 只要两个 key 算出来的 i 相同，就会进同一个哈希桶。

这里if做hash值判断，相等说明两个对象在一个桶里，原先桶里已经有一个对象，那table[i]拿到的就是旧链上的对象，再进行((k = e.key) == key || key.equals(k))，这里在put的时候，就要先put TemplatesImpl,再put Proxy

怎么让Hash值相等呢？

TemplateImpl的 hashCode() 是一个Native方法，每次运行都会发生变化，所有选择去看Proxy.hashCode

hashCode经invoke转到hashCodeImpl()

AnnotationInvocationHandler::hashCodeImpl()

这里是遍历memberValues的每一个key和value,计算(127*key.hashCode)^value.hashCode,如果key.hashCode为0，一个数与0异或结果是他本身，就是value.hashCode

这里有一个可用字符串f5a5a608他的hashCode为0
